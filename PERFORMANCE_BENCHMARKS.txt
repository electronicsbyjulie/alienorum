PER-PROPOSAL PERFORMANCE REVIEW

Status: independent review of all eighteen existing proposals complete. P042 is disabled by default; other inconclusive results remain labeled as such.

Method
Each proposal has a separate PERF_Pxxx compile-time switch in src/performance_options.h.
Production builds fold these switches to constants. A private benchmark build also permits
one reference path at a time, while keeping the other implemented proposals enabled.
Shared infrastructure remains present where another enabled proposal relies on it.
These are marginal before/after comparisons, not additive speedup claims.

The benchmark fixes simulation epoch, animation phase, camera, world, map, and route.
It alternates AB/BA order over repeated paired runs, excludes setup and warmup frames,
and waits for GPU completion. Images must match exactly, except for the established
P042 two-channel-level tolerance for CPU/GPU antialias arithmetic. GPU identity,
viewport, sample counts, workloads, and raw per-pair timings accompany every result.
Native hidden-window GL tests draw only into their own window; user images and layouts
are untouched. Software-renderer results are identified explicitly and cannot establish
performance on other GPUs. No production universe or catalog is changed.

Existing proposals
P001-P005, P020-P024, P031, P039-P042, P050-P052: initial comparisons completed; confirmations pending.
Consistent regressions will receive a default PERF_Pxxx value of 0 and a disabled status
in FRAME_RATE_AUDIT_PROPOSALS.txt. Neutral existing results will not be called gains.

Requested implementation queue, in order
P006, P007, P008, P012, P013, P018, P025, P026, P028, P029, P030, P036, P037,
P043, P049, P067, P068, P073, P077, P078, P090, P094, P095, P101, P105, P108.
Each item will receive its own implementation, paired measurements, correctness checks,
status entry, commit, and push. New changes without demonstrated improvement remain
available behind a default 0 switch. A two-minute pause separates completed fixes.

CORE-FRAME REVIEW AND DEFAULT DECISION
The core-frame runs add coordinate/projection processing to every horizon sample and
record main-thread CPU time alongside GPU-complete wall time. The epoch and animation
inputs repeat for each mode; the drawable is verified as 1280 x 720. Core runs use five
paired blocks of eight frames; extended confirmations use nine blocks of twenty-four
frames. Corrected raster/color confirmations use nine blocks of sixteen frames.

P022's final before path is the original direct projection loop from e0eead1, without
sector bounds or the camera scratch pass. P024's scalar before path omits tile metadata
allocation/maintenance. The initial P022/P024 rows are superseded by the corrected raster
run. P050's final before path omits cache lookups, inserts, and retained storage. Its later
confirmation rows in PERFORMANCE_BENCHMARK_CONFIRM_RESULTS.csv overlap a private build
and are rejected; only the separate fresh COLOR_RESULTS run informs its final status.
The source list used by P050 was already provided by P005 and is not credited again.

Evidence priority: corrected raster rows for P022/P024, fresh color rows for P001/P050,
extended confirmations for P039/P042, and core-frame rows for the other proposals.
The corrected raster run uses the local three-object fixture; the catalog/core/color runs
also include the 42,120 synthetic remote/background objects. Each comparison retains
identical inputs and other enabled proposals within its own run. Cross-run percentages
are not pooled or added. Descriptive paired-median 95% bootstrap intervals use a fixed
random seed and 4,000 resamples; zero-crossing intervals are reported as mixed/neutral.

Decision: #define PERF_P042 0. All three sweeps have positive median wall-time changes
for instancing in both forest workloads. The extended still view is +1.19% with interval
[+0.28%, +4.02%]; the core walking view is +5.08%. Reduced CPU work does not compensate
for slower GPU-complete frames on this Intel HD 2000. The CPU painter keeps the same
contours, trunk attachment, sightline aspect, density, shadows, and ordering. The instanced
implementation remains available for an explicit build comparison on another GPU.

No other old proposal is consistently slower across the accepted comparisons. P022/P024
and several smaller caches are mixed/neutral; they are not established gains. P001's
membership construction is shared with P002, so its isolated row measures the additional
cached predicate lookup rather than deleting infrastructure another enabled fix uses.
The new requested queue retains the stricter policy: an unproven new optimization defaults
to 0. A zero default is a benchmark decision, not permission to remove physical data or
relax visible behavior. Source/scene/hardware differences can change future results.

Post-decision verification: 99 enabled rendering checks and all 14 housekeeping checks
pass. Eight optional GPU checks skip, including the two now-disabled P042 comparisons.
The pre-decision private GPU comparisons exercised P042 and stayed within one channel
level. The application builds. User visual checks and other hardware remain separate.

CMake verification also passes after the default change. The benchmark executable has
an explicit Make target and is excluded from ordinary test builds/runs. To compare a
shipping-disabled implementation, add its override (for example -DPERF_P042=1) to the
private build's SANFLAGS alongside ALIENORUM_PERFORMANCE_BENCHMARK; production defaults
stay at 0. No benchmark executable, fixture, report, or raw CSV is a runtime dependency.

P006 — ARMED-ALERT REGISTRY (enabled: PERF_P006=1)
Flag assignments/copies and published armed objects invalidate a coalesced registry.
Retained object references survive catalog reordering; flag clearing, destruction,
array replacement and count changes refresh membership. Empty steady-state checks
perform no catalog scan. Original crossing tests, history resets, muted callbacks,
and soft-deletion behavior are preserved. The original scan remains the before path.

twenty-four frames per mode. Raw results: PERFORMANCE_BENCHMARK_P006_RESULTS.csv.

Both workloads improve consistently. Keep P006 enabled. Checks: eight sound,
73 serialization, 99 rendering and fourteen housekeeping passes; eight optional GPU
comparisons skip. Make application build passes. No runtime file or save schema is added.

P007 — ACTIVE-WORLD ECLIPSE COLLECTION (enabled: PERF_P007=1)
Retain the sorted active-world membership already assembled for P002. Collect casters
from that list instead of traversing background stars. Retain light-source ordering
while object/source membership matches, but read radius and light source every frame;
all positions and shadow geometry remain live. Membership changes rebuild grouping.
The original collector/sort is retained behind PERF_P007=0. This measures the marginal
collector change with P002 still enabled, not a second claim for P002 membership work.
