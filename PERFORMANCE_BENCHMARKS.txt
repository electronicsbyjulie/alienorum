PER-PROPOSAL PERFORMANCE REVIEW

Status: initial component sweep complete; longer core-frame confirmations are running.

Method
Each proposal has a separate PERF_Pxxx compile-time switch in src/performance_options.h.
Production builds fold these switches to constants. A private benchmark build also permits
one reference path at a time, while keeping the other implemented proposals enabled.
Shared infrastructure remains present where another enabled proposal relies on it.
These are marginal before/after comparisons, not additive speedup claims.

The benchmark fixes simulation epoch, animation phase, camera, world, map, and route.
It alternates AB/BA order over repeated paired runs, excludes setup and warmup frames,
and waits for GPU completion. Images must match exactly, except for the established
P042 two-channel-level tolerance for CPU/GPU antialias arithmetic. GPU identity,
viewport, sample counts, workloads, and raw per-pair timings accompany every result.
Native hidden-window GL tests draw only into their own window; user images and layouts
are untouched. Software-renderer results are identified explicitly and cannot establish
performance on other GPUs. No production universe or catalog is changed.

Existing proposals
P001-P005, P020-P024, P031, P039-P042, P050-P052: initial comparisons completed; confirmations pending.
Consistent regressions will receive a default PERF_Pxxx value of 0 and a disabled status
in FRAME_RATE_AUDIT_PROPOSALS.txt. Neutral existing results will not be called gains.

Requested implementation queue, in order

P043, P049, P067, P068, P073, P077, P078, P090, P094, P095, P101, P105, P108.
Each item will receive its own implementation, paired measurements, correctness checks,
status entry, commit, and push. New changes without demonstrated improvement remain
available behind a default 0 switch. A two-minute pause separates completed fixes.

INITIAL COMPONENT SWEEP
Hardware: Mesa Intel(R) HD Graphics 2000 (SNB GT1), native hidden GL window.
Viewport: 1280 x 720. Five alternating paired blocks, eight measured frames per mode.
Synthetic catalog: 30,000 background stars, 120 remote hosts, 12,000 dormant planets,
and the local three-object surface fixture. Catalog scenes include the coordinate pass
and three filtered consumer traversals. Other scenes isolate horizon preparation/drawing
and GPU completion. Core-frame confirmations also run the coordinate pass for those scenes.
A complete application includes additional UI/background drawing and can have other costs.
Epoch, animation phases, route and material inputs repeat between the two paths.
All comparisons pass: exact images and catalog state, with P042 within one channel level.
Raw pairs: PERFORMANCE_BENCHMARK_RESULTS.csv. Negative changes mean lower frame time.
These are local marginal results; improvements cannot be added across proposals.
No default has been disabled solely on these short initial samples.

The P001/P002 membership structures overlap: the P001 comparison changes cached
activity-predicate lookup while retaining the membership data used by P002. P005
already supplies the bright-source list; P050 measures its additional color/storage reuse.
Existing neutral/mixed results remain unconfirmed, rather than being labeled improvements.
The full native correctness run passes 101 rendering checks and 14 housekeeping checks.
Six optional terrain GPU checks remain skipped. Benchmark controls compile out of ordinary
production paths; the mutable per-proposal controls exist only in the private benchmark build.

Reproduce a private build:
mkdir -p /tmp/alienorum-perf-objects/{internal,imgui,igfd,tests} /tmp/alienorum-perf-bin
make -j2 OBJ=/tmp/alienorum-perf-objects BIN=/tmp/alienorum-perf-bin SANFLAGS=-DALIENORUM_PERFORMANCE_BENCHMARK=1 /tmp/alienorum-perf-bin/performance_benchmark_test
python3 tools/run_performance_benchmark.py --output /tmp/review.csv
This uses its own hidden window and synthetic objects, not a production universe.
