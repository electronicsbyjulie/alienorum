# Alienorum Project Rules & Guidelines for AI Agents

## Brace Style
- **Generally use Allman style braces; NEVER use K&R style** for all multi-line code blocks, functions, control structures (`if`, `else`, `for`, `while`, `switch`, `try`, `catch`, `finally`), classes, structs, and namespaces across all languages. However, if a statement or inline function can fit on one line or is already one line, you may write it/leave it as one line, even if it contains braces.
- Otherwise, each opening brace (`{`) and its closing counterpart (`}`) MUST always match the same level of indent.
- Never end a line with an opening brace and never misalign a pair of braces by their indentation.
- After-block keywords such as `else`, `else if`, `catch`, `finally` MUST start on a new line following the closing brace.

## Runtime Files & Packaging Rule
- **Mandatory Packaging Sync:** Any time new runtime dependency files (such as `.dat` files, `.json` catalogs, fonts, shaders, audio, or static texture maps) are added to the repository that are **not** auto-generated by the application or auto-downloaded from the internet at runtime, they **MUST** also be added to the CMake / vcpkg installation rules in [`CMakeLists.txt`](CMakeLists.txt) (and the packaging scripts under [`package/`](package/)) so they are bundled into the release installer (`Alienorum-<version>-win64.exe`).
- Do not let runtime data files be added to the source tree without verifying their inclusion in the Windows installer target.

## Data Availability and Uncertainty
- The simulation always prioritizes having available data over having none. Never reject, omit, clear, or replace information solely because it is uncertain, approximate, inferred, or estimated, unless replacing it with more accurate or more trustworthy information.
- A supplied value followed by `?` must always be used exactly as the same value without `?`, including angles, periods, unit conversions, status flags, rendering, and saved/reloaded data. Preserve uncertainty annotations or provenance where supported without withholding the value from the simulation.
- Missing values remain distinct from supplied estimates: a standalone `?` does not invent a value, and explicit zero is valid data. Retain validation for malformed input and impossible representations; uncertainty alone is never a validation failure.

## README Readability
- The target demographic for this app is popular science enthusiasts, not career programmers, though the latter are also welcome.
- Don't pollute the main part of the README file with a bunch of hard-to-read, dry, information dense, boring details about the program internals, or details about the code, the calculations, code files, or specifics that most users won't care about. Leave that stuff for the For Developers section, and even then, before adding anything, ask if it will truly be useful to developers working on the project or if it is just code documentation that we might one day designate  aplace for but it isn't the README.
- Keep the documentation at a family science center level of writing.
- Keep anything required to build and run the app.

## References Folder
- The `refs` folder contains scientific publications that may be protected by copyright. Don't commit anything from this folder into Git.
- If doing research for a task and you use information from a published article, drop that article's PDF in this folder if you have access.
- Do not mention the refs folder in any plan or .md file.

## When Testing Loading the App
- If you are not testing anything dependent on exoplanets, you may run the app with the `noexo` CLI arg. That skips startup exoplanet loading, resulting in a significantly faster load time (a few seconds of savings). F2 loads `universe.json`.
- If you are not testing anything dependent on artificial satellites, you may run the app with the `nosat` CLI arg. That will save about 15-20 seconds of load time by skipping satellites altogether, however that feature will be completely unavailable until the app is restarted.
- The `noexo` and `nosat` args may be combined for maximum loading efficiency.
